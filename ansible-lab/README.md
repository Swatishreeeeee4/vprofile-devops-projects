# Ansible: multi-OS server configuration with roles

Configuration management for a small fleet: **web01 (Ubuntu 22.04)**, **web02 (Rocky Linux 9, RedHat
family)** and **db01 (Ubuntu)**, managed over SSH from an Ansible control node. Everything runs locally in
Docker, and the playbook is **idempotent**: the second run changes nothing.

> Built while following the *Decoding DevOps* course (Imran Teli, Udemy), Section 22; extended with SSH
> hardening, validation, a DB role and a containerised lab. See **What I changed**.

## Layout

```
ansible-lab/
├── ansible.cfg                 inventory, remote user, key, become
├── inventory/
│   ├── hosts.ini               [web] web01 web02, [db] db01
│   └── group_vars/             all.yml (users, packages, banner), db.yml (db name/user)
├── site.yml                    all → common, web → webserver, db → dbserver
├── roles/
│   ├── common/                 packages (apt/dnf by OS family), group + users (loop), sudoers (visudo-validated),
│   │                           motd template (facts), SSH hardening drop-in + handler, sshd -t check
│   ├── webserver/              nginx on both families, templated page, reload handler, uri self-test
│   └── dbserver/               MariaDB, database + least-privilege user (community.mysql), no_log
├── images/                     Dockerfiles for the control node and the Ubuntu/Rocky managed nodes
└── docker-compose.yml
```

## Run it

```bash
cd ansible-lab
mkdir -p .keys && ssh-keygen -q -t ed25519 -N "" -f .keys/id_ed25519     # lab key (git-ignored)
docker compose up -d --build
docker exec control ansible all -m ping -o          # pong from all 3 nodes
docker exec control ansible-playbook site.yml       # first run: changes
docker exec control ansible-playbook site.yml       # second run: changed=0 (idempotent)
docker compose down
```

## Verified results

| Check | Result |
|---|---|
| Run 1 | ok=14–16, **changed=11**, failed=0 on all hosts; handlers reload sshd and nginx |
| Run 2 | **changed=0** on all hosts (idempotent) |
| Web pages | web01 "Ubuntu 22.04", web02 "Rocky 9.3": same template, OS-specific web roots |
| SSH hardening (`sshd -T` on Rocky) | permitrootlogin no, passwordauthentication no, maxauthtries 3 |
| DB | database `accounts`, user `vprofile` (rights on `accounts.*` only) |
| Drift | motd overwritten by hand → re-run → exactly 1 change restores it |

## Concepts shown

Inventory and groups · ad hoc commands · playbooks and roles · `group_vars` · facts (`ansible_os_family`,
`ansible_distribution`) · conditionals (`when`) · loops · `copy`/`template` modules · handlers · `validate`
before installing config files · `changed_when` · `no_log` · collections (`community.mysql`) ·
`lookup('password')` for secrets that never go to Git · `--limit`.

## What I changed compared with the course

- **SSH hardening** role task with a drop-in config, a full `sshd -t` check and a reload handler.
- Config files are **validated before they're installed** (`visudo -cf` for sudoers).
- **DB role** with a least-privilege user; the password is generated by `lookup('password')` into a git-ignored
  file and hidden with `no_log` (production: Ansible Vault or a secrets manager).
- **Containerised lab** (Ubuntu + Rocky managed nodes, control node) instead of 3 EC2 instances: free and
  rebuildable in a minute.
- Course zip shipped private keys (`vprofile-key.pem`); this repo commits no keys.

## Debugging notes

| Symptom | Cause | Fix |
|---|---|---|
| ssh: "UNPROTECTED PRIVATE KEY" | Files bind-mounted from Windows appear world-readable | Control node copies the key and `chmod 600` at start |
| `dnf install curl` conflicts on Rocky | Rocky ships `curl-minimal` | Don't install `curl` there (it's already provided) |
| No systemd inside containers | Containers run one process | Manage nginx via its binary (`nginx`, `nginx -s reload`), signal sshd directly; MariaDB via its init script |
